# CLM Platform Engineering & UX Notes — November 20, 2026

## Critical UX & Deployment Feedback

### 1. Dedicated Enrollment Token Box in Gateway Modal
* **User Feedback:** The bootstrap enrollment token was buried inside the 1-line curl script or truncated (`clm_enroll_NzBkY...`) in the CloudFormation overview, making it confusing to locate and copy when AWS CloudFormation asks for the `EnrollmentToken` parameter.
* **Resolution Required:**
  * Add a dedicated, full-width **Bootstrap Enrollment Token** card right at the top of the modal (or within the CloudFormation tab).
  * Provide an explicit, dedicated **"Copy Token"** button that copies only the raw `clm_enroll_...` string to the clipboard with one click.
  * Provide a clear copy button for **"Control Plane URL"** (`https://<backend-domain>/api/v1`) as well.

### 2. AWS CloudFormation Launch Enhancements
* AWS CloudFormation requires an Amazon S3 URL if launching via `templateURL`. Since custom customer deployments upload YAML directly:
  * Maintain the two-step flow:
    1. **Download Stack Template (`clm-satellite-gateway.yaml`)**
    2. **Open AWS CloudFormation Template Upload Console** (`#/stacks/create/template`)
  * Display explicit copy boxes for:
    * `EnrollmentToken` (Single-click copy)
    * `ControlPlaneUrl` (Single-click copy)

### 3. Agent & Installer Integrity
* Verified and resolved in `install.sh`:
  * Mandatory shebang `#!/bin/bash` on line 1 for AWS EC2 `cloud-init` compatibility.
  * Node.js runtime presence check and installation must occur **before** generating `/opt/clm-gateway/gateway.js` and `run.sh`.
  * Response parsing must extract `resp.gatewayId || resp.id` from `/ingress/gateway/enroll` payload.
  * Dynamic detection of EC2 instance local VPC IP (`hostname -I | awk '{print $1}'`).
